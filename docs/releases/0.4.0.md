# metor 0.4.0 release preparation

Release notes: the 0.4.0 section in CHANGELOG.md. Generate the exact GitHub body with
`node scripts/check-release.mjs --notes`.

## Verified locally (2026-09-11)

- Version metadata agrees across VERSION, desktop/mobile manifests and locks, native
  mobile versions and relay metadata. Release notes have one Unreleased section.
- 29 core tests pass, including shared RAM admission, lifecycle, auth, commands and
  persistent local RAM settings.
- The arm64 0.4.0 Space image builds and passes 56 smoke checks without inference calls.
- `node scripts/release-upgrade.integration.mjs` passes against the published 0.3.0 image:
  bots, chat history, files, all sign-in volumes, a paired session and saved 2.5 GiB RAM
  survive upgrade and a subsequent ordinary restart. Test data/volumes are isolated.
- The unsigned arm64 Mac app packages at version 0.4.0 and opens its connection screen
  with a separate test profile. The directory-only test package has no updater metadata;
  automatic installer updates were not tested.
- Workflow YAML parses. The image workflow now checks metadata/core tests, then runs
  smoke checks on each built architecture before exposing image tags and creating a release.

## Publication sequence

1. Commit and push the reviewed release preparation. Wait for the image workflow on main.
2. Tag that same verified commit `v0.4.0` and push the tag. The image workflow creates the
   versioned multi-architecture image and GitHub release with notes and install.sh.
3. Verify both image architectures, release notes and installer download in GitHub.
4. Update the Homebrew formula/tap only after the published tag archive checksum can be
   computed. The checked-in formula currently remains a valid reference to 0.3.0.

The desktop workflow is separate (`desktop-v*`, or manual builds without publication).
Do not imply that the core v0.4.0 tag creates desktop installers or mobile store releases.
Windows/Linux desktop builds, mobile store distribution, signing/notarization and the
installer's automatic-update path remain separate validation/distribution steps. The local
Mac package is unsigned. Linux Docker live RAM resizing has not been verified on a real
Linux host. No production subscription inference was used for this preparation.
