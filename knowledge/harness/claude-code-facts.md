| **In-session crons work in the stream harness** | `CronCreate` (`* * * * *`, recurring) in an SDK streaming session: the routine **fires to the minute as its own turn** (tool calls + text appear in the history) and **survives both host restart and container restart** – the cron is attached to the session (resume carries it forward), not to the process. ## Consequences for metor

- **Refine ADR-0002:** the computer (container) bounds file system and shell, not messages.
  Bots can reach every session of the user and be reached by every one (`crossSessionInbound`).
  → Messaging rules in the bot template (reply only to the sender, no foreign sessions, no fan-out,
  no ack loops); long-term an allow-list of senders via hook.

- Supervisor: start → read `sessionId` from `agents --json` → remember in `bot.json` → `--resume` on next start → adopt the new ID → `rm` the old entry.
- Set trust before every start (idempotent).
- Login volume (`metor-claude`) separate from the workspace; never mount the host's `~/.claude`.
